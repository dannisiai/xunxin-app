# 寻信账号部署

## 复用已有 Sub2API 账号

本地已选择 Sub2API 服务作为账号来源，连接地址为 `https://xunxin.shop`，API 地址为 `https://xunxin.shop/v1`。复用同一套邮箱和密码，不复制上游密码、不另建用户表。应用调用费用计入当前 Sub2API 账户余额，应用内不会继承管理员权限。

服务端环境变量（仅存于忽略提交的 `.env.local` 或部署平台私密环境变量）：

```dotenv
NEXT_PUBLIC_SELF_HOSTED_MODE=false
ACCOUNT_AUTH_PROVIDER=sub2api
SUB2API_BASE_URL=https://your-account-server.example
# HTTPS 反向代理部署时设置应用的公开来源；本机直连可省略
ACCOUNT_APP_ORIGIN=https://your-xunxin-app.example
ACCOUNT_GATE_SECRET=独立随机密钥至少32位
# 可选：默认在项目 .data/sub2api-sessions；正式部署应配置持久目录
SUB2API_SESSION_DIR=/var/lib/xunxin/sub2api-sessions
```

修改后重启开发服务器；正式部署需要重新构建。地址接受 HTTPS 根地址或 `/api/v1` 地址，使用标准证书校验，拒绝明文 HTTP、重定向及地址中的凭据。不需要 Sub2API 管理员密钥、数据库密码或 Resend 配置。

注册、登录、邮箱验证码、TOTP 二次验证、当前用户、刷新令牌、退出和修改密码都通过寻信自己的 `/api/auth/*` 适配对应上游接口。登录成功前调用上游 `/auth/me` 确认身份。密码只作转发，不落库或写日志。修改密码会影响共用的 Sub2API 账号，并退出本机登录。

窗口从公开设置读取注册开关，按上游要求显示必填密码、可选的邮箱验证码和邀请码。服务器的注册开关须开启才能接收新用户；新账户默认余额为零，不会自动赠送费用。邮箱验证码仅用于注册。TOTP 按登录返回的挑战处理，不跳过验证。如果以后开启人机验证或账号协议确认，此适配器会停止内嵌登录并提示使用账号中心，尚未接入这些第三方验证组件。

浏览器仅持有随机会话 ID 的 HttpOnly、SameSite=Lax Cookie；上游访问令牌和刷新令牌在服务端以 AES-256-GCM 加密保存，绑定账号服务地址。刷新使用文件锁避免同一主机的并发令牌轮换，原始会话最长 30 天，不会无限续期；重启保留会话目录和密钥即可恢复。退出删除本机会话，尝试撤销本次上游刷新令牌。若上游不可达，会明确提示远端会话未撤销；不会撤销其他设备的账号会话。

此会话存储适合**单台、具有持久磁盘的 Node 主机**，不适用于无持久磁盘的 Serverless 或多主机扩容；这些部署须先换用共享会话存储和分布式锁。目录限制为服务进程用户读写，必须在静态站点、备份公开文件、Git 和 APK 源码打包之外。Linux 自动创建的目录／文件权限为 0700／0600，Windows 正式部署须配置对应 NTFS ACL。密钥轮换会使原有会话失效。异常退出留下的孤儿锁仅在确认原进程已退出后恢复；若恢复锁自身遗留，应先停止服务，再清理对应 `.lock`／`.lock.recover`。不要清理活动服务的锁。

### 自动凭证、余额调用与重置

云端迁移 `250_account_api_credentials.sql` 将普通用户创建和凭证生成放在同一个数据库事务中，并以部分唯一索引限制每个普通用户只能有一个未删除密钥。管理员已有运维密钥保留；管理员在寻信内使用的托管凭证仍只有一个。默认调用分组由 `account_credential_default_group_id` 设置选择，必须是启用、非专属、按余额计费的分组；未配置时优先选择符合条件的 OpenAI 分组。

云端 `GET /api/v1/user/credential` 向已登录的账户返回其调用凭证；`POST /api/v1/user/credential/reset` 使用 `Idempotency-Key` 防止重试重复重置。普通用户的密钥列表及用量响应不返回明文密钥。重置只替换同一记录的密钥，保留 ID、余额、用量、配额、限速和有效期。网关除清理缓存外，还核对数据库中的当前密钥，避免重置时旧密钥被并发查询重新写入缓存。已经通过鉴权的在途调用可正常结束。

寻信自身的 `GET /api/auth/credential` 与 `POST /api/auth/credential` 都要求 `X-Account-Id` 为页面显示的完整账户 ID。适配层将它与当前已验证的登录账户严格比较；缺少或不匹配时返回 409，不向上游读取或重置凭证，页面提示重新打开账户凭证。这样，其他标签页切换账户后，旧页面不会误读或重置新账户的凭证。网页前后端需同步更新，旧网页应刷新；Android 的页面和适配层随新 APK 一起更新。

充值中心显示余额与用量，账户凭证页显示 API 地址、密钥、默认模型和凭证重置入口。页面不提供复制地址或凭证的按钮；可见内容仍可截图或手动记录，密钥也可以从账户凭证响应中读取。云端登录时，聊天与文本辅助功能自动使用同一账户配置；本地只持久保存按账号区分的模型选择和非秘密绑定标记。`/api/cloud/v1/*` 使用账户会话访问云端受限代理，云端取得托管凭证后交由现有模型网关处理。余额检查及扣款仍由 Sub2API 网关负责。自动模型从账户可用列表选择；充值支付渠道未配置时，通过兑换码或管理员调整余额。

隐藏密钥后的云端代理与应用必须配套更新。旧应用依赖云端接口返回明文密钥，云端升级后需要同步更新这些应用。已经复制或泄露的旧密钥不会因隐藏页面自动失效，重置凭证后才会失效。

Android 构建必须设置 `NEXT_PUBLIC_SELF_HOSTED_MODE=false`。本机 Node 适配层使用每次安装生成并持久保存的独立秘密加密会话，连接日本服务器；会话目录放在应用私有文件目录，跨应用资源版本保留。打包脚本排除 `.env*`、会话目录及日志，不能将服务器会话密钥或真实 API Key 打包进 APK。源码修改不会更新已安装的旧 APK，需重新构建并安装。

实现依据为上游公开代码，但部署服务器的策略和接口响应优先：

- [认证路由](https://github.com/Wei-Shaw/sub2api/blob/main/backend/internal/server/routes/auth.go)
- [认证请求与响应](https://github.com/Wei-Shaw/sub2api/blob/main/backend/internal/handler/auth_handler.go)
- [修改密码接口](https://github.com/Wei-Shaw/sub2api/blob/main/backend/internal/handler/user_handler.go)

本次按用户要求不运行测试、不注册试用账户、不发起模型调用，也不重置现有账户凭证。编译只用于生成部署产物，不能替代端到端验收。

## 原有 Supabase 邮箱账号方案

未选择 Sub2API 时保留原有 Supabase 方案。启动页底部箭头会打开注册／登录窗口，默认显示邮箱注册。本地单机模式提供「继续本地使用」，明确选择后以本地用户进入，不发送验证码，也不创建云端账号。启用账号校验的部署不会显示本地使用入口。此方案的账号数据存储在自己的 Supabase 项目，验证码通过 Resend 发送。

1. 新建自己的 Supabase 项目，依次在 SQL Editor 执行 `docs/account-supabase.sql` 和 `docs/xunxin-email-auth.sql`。已有项目同样需要执行两个脚本来升级。保留既有数据，先备份再升级。
2. 在 Resend 配置并验证你自己的发信域名，创建 API Key。使用这个域名下的发信地址。
3. 在部署平台的服务端环境变量中设置：
   - `NEXT_PUBLIC_SELF_HOSTED_MODE=false`（修改后需重新构建）；
   - `SUPABASE_URL` 和 `SUPABASE_SERVICE_ROLE_KEY`；
   - `RESEND_API_KEY` 和 `REALITY_BRIDGE_EMAIL_FROM`（例如 `寻信 <hello@已验证的域名>`）；
   - `XUNXIN_EMAIL_CODE_SECRET` 和 `ACCOUNT_GATE_SECRET`，分别使用独立的随机长字符串，前者至少 32 位。
4. 重新部署后用真实邮箱测试注册、验证码登录、可选密码登录、退出和失效验证码。确保通过 HTTPS 访问；不要将 service role、邮件 API Key 或密钥放入 `NEXT_PUBLIC_` 变量或提交到 Git。

验证码 10 分钟有效，最多尝试 5 次，同一邮箱和用途至少间隔 60 秒，同一来源一小时最多请求 20 次。部署平台应正确设置可信的客户端 IP 转发头，并配合平台的请求限速；密码登录的现有限速是单实例内存限速，多实例上线前需使用共享限速或网关防护。

## 数据范围

后续按设备所有者要求增加了[本机共用人设存档](shared-local-personas.md)：角色、人设与用户身份头像通过固定公共文件在所有登录账号间共用，不按账号区分。这一功能改变的是这些指定资料的共享范围；下述数据库隔离仍用于聊天、认证信息和其他数据。原生目录访问需要新 APK 及用户系统授权。

聊天、角色、主题、语音方案和个人配置现在按服务器确认的完整账号 ID 保存。页面在应用模块运行前建立固定的账号空间，统一隔离 localStorage、sessionStorage、IndexedDB 和 CacheStorage；退出或切换账号会停止旧页面的存储、请求、流式响应、WebSocket 和通知，再重新载入。其他标签页也会同步失效，返回原账号后可继续使用自己的资料。账号身份不从可导入的备份记录读取。服务器对依赖登录 Cookie 的业务 API 同时核对页面账号；未匹配时拒绝访问。

升级前没有记录归属的数据库、键值和旧云备份原样保留，不自动分给第一个登录的人，不自动删除。所有账号先使用各自的新资料空间；后续确认归属后再单独迁移。本地导入是用户主动转移资料的操作，只能写入当前账号的逻辑数据，不能借备份指定其他账号的物理数据库或身份记录。云备份引擎在原存储桶下按 `accounts/<账号ID>/` 分目录，新账号不会列出或恢复旧的无归属备份。共享存储客户端仍供现实桥和微信工具使用，其文件协议没有改动。

PWA 不再缓存已登录页面，断网重新打开时显示联网提示；已有页面不因此自动清空本地资料。切换账号时会退订旧推送并关闭已有通知，新账号需独立启用推送。账号使用独立的推送 Worker scope，旧页面延迟清理不会退订新账号的订阅。系统直接处理的声明式通知使用通用文案，点击动作由同源入口再次核对账号。Android 同步停止旧账号的后台连接、悬浮窗、来电页和提醒，并在处理旧通知的接听动作时再次核对账号。屏幕适配、系统权限、应用更新、安装级会话加密秘密等仍属设备设置。

这些控制解决应用内正常登录、退出、切换账号和旧页面的串用，不提供针对设备所有者、开发者工具或任意同源恶意脚本的浏览器沙箱。跨设备同步仍需用户单独配置云备份。本次源码更新需网页前后端及个人推送部署包配套发布，Android 需重新构建安装；旧 APK 不会因源码修改自动更新。

MCP OAuth 的授权 state 也绑定发起授权时的账号。授权窗口打开后若切换账号，回调返回 409，不把原账号的授权码写入新账号；需回到原账号重新授权。升级前仍未完成的旧授权窗口同样需要重新发起。
