# 向量记忆

向量召回默认开启。未保存设置和旧设置缺少此项时均采用开启；用户明确关闭过的选择继续保留，可在资源库的记忆设置中重新开启。

云端账户复用聊天的账户、API 地址、会话鉴权和余额计费。向量请求使用独立的 `embeddingModel` 字段，默认发送 `__account_default__`，由服务端从当前账户可用模型中选择向量模型，不改变 `defaultModel` 的聊天选择。同一模型若确实支持 embeddings，也可在自定义配置中将两个字段设为同一个模型名。不要求另一套密钥。

当前自动发现兼容常见 embed、bge、m3e、text2vec、e5、gte 名称。名称识别不是上游能力探测：账户分组必须实际提供支持 `/embeddings` 的模型。无可用向量模型时返回明确错误，普通记忆召回继续工作；不会把聊天模型冒充向量模型。此修复没有为线上分组新增模型，也未发起真实付费请求。

新建和编辑长期记忆时生成向量并保存实际模型归属。向量必须是有限数值组成的非零数组。查询只比较同服务端地址、提供商、实际模型且维度相同的向量；缺少归属的旧向量不直接参与比较。

长期记忆全部可以放入用户设置的 Token 预算时仍按原逻辑全部注入，不需要额外生成查询向量。超出预算后才执行语义排序；旧记忆按需每次最多补建四条，采用与查询相同的模型，保留原文。后台补建只更新仍存在、内容和更新时间均未变化的记录，不恢复已删除资料、不覆盖用户编辑。暂未完成补建的资料仍可通过关键词和时间回退参与召回。

相关记忆文本和查询上下文会发送至模型服务，可能消耗账户余额。不开机批量重建全部记忆。前后端需配套更新；源码修改不会自动更新线上网页或已安装 APK。

回归检查：`node --test scripts/test-vector-memory.cjs scripts/test-managed-account-gateway.cjs scripts/test-cloud-voice-settings.cjs`。测试使用假模型响应，覆盖实际生成函数、模型归属、旧向量补建、关闭开关、普通召回和云端模型路由；不代表线上模型已实测可用。
