# App「使用声明」弹窗排查与修复

2026-11-12 核对源码及已发布的 1.0.4、1.0.8 APK，确认这两个安装包均包含三条自动显示同一声明的链路。声明标题为「使用声明」，正文提到原仓库 `xiaolongbao0709/ai-virtual-phone`，包含「那么你被骗了」等文字。

| 源文件 | 原触发入口 | 编码方式 |
| --- | --- | --- |
| `components/media-maintenance-scheduler.tsx` | 启动约 45 秒后的媒体维护任务 | 累加数字差值 |
| `lib/bg-tone.ts` | 运行满 60 秒后的状态栏取色更新 | 倒序读取数字并减 64 |
| `lib/qa-error-log.ts` | 报错收集启动约 90 秒后，以及恢复前台时 | 数字与位置掩码进行异或 |

三条链路读取 `ai-phone.typeset.memo` 排版缓存中的文字指纹，并共用 `ai_phone_tone_calib_v1` 时间记录。指纹未命中时先记录首次时间，间隔满 24 小时后才显示；这解释了首次安装或刚更新时可能没有弹窗。完整正文不以明文保存在源码或编译产物中，仅搜索标题、原仓库地址或已删除的离线推送公告会漏检。

修复删除三处编码载荷、检查函数、计时和弹窗 DOM 创建逻辑，保留媒体清理、状态栏颜色适配和全局报错收集。无需改写用户本地的提示记录。

`scripts/test-app-popup-removal.cjs` 模拟超过一天的旧时间记录、延时启动和恢复前台，确认不再创建弹窗，同时验证原功能继续运行。原源码在三个弹窗用例上失败，修复后通过。

Android 打包脚本调用 `scripts/check-app-popup-bundle.cjs` 检查实际编译后的前端文件；若仍含这三处编码载荷或旧离线推送公告，则阻止打包。源码修改需要重新构建并安装新版 APK，已发布的 1.0.8 安装包不会随本地修改改变。
